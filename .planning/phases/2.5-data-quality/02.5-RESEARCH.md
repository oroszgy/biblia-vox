# Phase 2.5: Data Quality & Correction - Research

**Researched:** 2026-05-29
**Domain:** Bible text data quality — JSONL conversion, verse splitting, versification schema correction
**Confidence:** HIGH

## Summary

Phase 2.5 addresses three data quality issues preventing `bibliavox text validate --all` from passing for all 66 SZIT books. The current validation shows 57/66 books passing, with 9 books failing due to verse count mismatches and missing chapters.

**Root causes identified:**
1. The raw SZIT data is a nested Python dict (`{book: {ch: {v: text}}}`) — needs conversion to flat JSONL for downstream pipeline consumption.
2. 67 verses contain embedded verse markers (`N)`, `((N))`, `(N)N`) — most are Psalms superscriptions where the target verse already exists (text cleanup only), but 4 verses need actual splitting.
3. The versification schema has errors: DAN 3 expects 91 verses (deuterocanonical additions not in SZIT), MAL is missing chapter 4, and several books have off-by-one discrepancies caused by source versification differences.

**Primary recommendation:** Process in three composable stages (JSONL → verse splitting → schema fixes), each a separate Taskfile target, with the validator as the acceptance gate.

### Pattern 1: JSONL Conversion

**What:** Transform nested SZIT dict to flat JSONL format.
**When to use:** First stage of the pipeline, produces intermediate artifact.
**Example:**

```python
# Source: New module bibliavox/text/jsonl_converter.py
import json
from pathlib import Path
from bibliavox.text.source import load_szit_json
from bibliavox.text.mapping import load_book_mapping
from bibliavox.text.normalizer import normalize_text

def convert_to_jsonl(output_path: Path, data_dir: Path | None = None) -> int:
    """Convert SZIT JSON to JSONL format.
    
    Each line: {"book": "GEN", "chapter": 1, "verse": 1, "text": "..."}
    Returns: number of verses written.
    """
    data = load_szit_json(data_dir)
    mapping = load_book_mapping()
    count = 0
    
    with open(output_path, "w", encoding="utf-8") as f:
        for english_name, book_data in data.items():
            if english_name not in mapping:
                continue  # Skip unknown books
            usx_code = mapping[english_name]
            
            for chapter_str, verses in book_data.items():
                chapter = int(chapter_str)
                for verse_str, text in verses.items():
                    record = {
                        "book": usx_code,
                        "chapter": chapter,
                        "verse": int(verse_str),
                        "text": normalize_text(text),
                    }
                    f.write(json.dumps(record, ensure_ascii=False) + "\n")
                    count += 1
    
    return count
```

### Pattern 2: Verse Marker Detection & Splitting

**What:** Detect embedded verse markers and either clean up or split text.
**When to use:** Second stage, operates on JSONL from stage 1.
**Example:**

```python
# Source: New module bibliavox/text/splitter.py
import re
from dataclasses import dataclass

# Three pattern types found in SZIT data
PATTERNS = [
    re.compile(r'\((\d+)\)(\d)'),   # (N)N — e.g., "(6)7" in 2Ki 11:6
    re.compile(r'\(\((\d+)\)\)'),    # ((N)) — e.g., "((54))" in 1Ki 22:52
    re.compile(r'\b(\d+)\)'),        # N) — e.g., "2)" in Psalms
]

@dataclass
class VerseMarker:
    """A detected verse marker in text."""
    pattern_type: str  # "N)", "((N))", or "(N)N"
    target_verse: int  # The verse number the marker points to
    position: int      # Character position in text
    raw_match: str     # The matched text

def detect_markers(text: str) -> list[VerseMarker]:
    """Detect all verse markers in text."""
    markers = []
    for pattern in PATTERNS:
        for match in pattern.finditer(text):
            markers.append(VerseMarker(
                pattern_type=pattern.pattern,
                target_verse=int(match.group(1)),
                position=match.start(),
                raw_match=match.group(0),
            ))
    return markers

def split_verse(text: str, marker: VerseMarker) -> tuple[str, str]:
    """Split text at marker position. Returns (before, after)."""
    before = text[:marker.position].strip()
    after = text[marker.position + len(marker.raw_match):].strip()
    return before, after
```

### Anti-Patterns to Avoid

- **Mutating raw data:** Never modify `data/raw/text/H_Kaldi_SZIT.json`. Always write to `data/processed/text/`.
- **Skipping NFC normalization:** Apply NFC during JSONL conversion, not as a separate pass. [VERIFIED: normalizer.py already has `normalize_text()`]
- **Hardcoding verse splits:** Don't hardcode which verses to split. Use regex detection so the solution generalizes.
- **Ignoring Psalms superscriptions:** The `2)` in Psalms verse 1 is NOT a split candidate — the target verse already exists. Only strip the marker text.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| JSON parsing | Custom parser | `json.loads()` / `ast.literal_eval()` | Already in source.py, handles Python literal format |
| Unicode normalization | Manual char handling | `unicodedata.normalize("NFC", text)` | Already in normalizer.py |
| Regex patterns | Complex string splitting | `re.compile()` with named groups | Standard, testable, documented |
| File I/O | Custom buffering | Standard `open()` with `encoding="utf-8"` | JSONL is simple line-by-line |

**Key insight:** This phase is pure data transformation — stdlib is sufficient. No new dependencies needed.

## Common Pitfalls

### Pitfall 1: False Positive Verse Markers in Psalms

**What goes wrong:** Treating `2)` in Psalms 3:1 as a split point creates a duplicate verse 2 (which already exists).
**Why it happens:** The regex `\d+\)` matches superscription references like "(Dávid zsoltára.) 2) Mennyien..."
**How to avoid:** Before splitting, check if the target verse already exists in the chapter. If it does, only strip the marker text — don't create a new verse.
**Warning signs:** Verse count increases after splitting when it shouldn't.

### Pitfall 2: Psalms with Both `2)` and `3)` Markers

**What goes wrong:** PSA 51:1, 52:1, 54:1, 60:1 contain both `2)` and `3)` markers. The `2)` is part of the superscription (e.g., "amikor Nátán próféta fölkereste"), while `3)` marks where the actual psalm text begins.
**Why it happens:** The SZIT source embeds the historical context between `2)` and `3)`.
**How to avoid:** Both target verses (2 and 3) already exist in the data. Strip both markers from verse 1 text, don't split.
**Warning signs:** Creating verse 2 from text that's actually part of the superscription context.

### Pitfall 3: Schema vs Source Mismatch (DAN 3)

**What goes wrong:** Schema expects 91 verses for DAN 3 (Catholic canon with deuterocanonical additions: Prayer of Azariah, Susanna, Bel). SZIT source has only 30 verses.
**Why it happens:** The schema was generated from szentiras.eu tdverse which includes deuterocanonical additions, but SZIT (Szent István Társulat) uses the shorter text.
**How to avoid:** Update schema to match SZIT reality (30 verses), not idealized canon. [VERIFIED: CONTEXT.md decision: "Schema vs source conflicts: Schema should match SZIT source, not idealized canon"]
**Warning signs:** Validator reports "Verse count mismatch" for DAN 3 after splitting.

### Pitfall 4: Off-by-One Discrepancies Are Schema Errors, Not Data Errors

**What goes wrong:** Books like JON, NAM, HAB, 2CO, 3JN show off-by-one verse count mismatches. These are NOT caused by embedded markers — they're genuine versification differences between SZIT and the schema source.
**Why it happens:** Different Bible traditions number verses differently (e.g., HAB 2 has 20 verses in SZIT but 17 in standard versification).
**How to avoid:** Update versification.json to match SZIT source counts. Don't try to "fix" the source data.
**Warning signs:** Verse counts that are off by exactly 1-3 across multiple chapters.

### Detecting Embedded Verse Markers

```python
# Source: bibliavox/text/splitter.py
import re

# Pattern priority: specific patterns first, general last
PATTERN_PN = re.compile(r'\((\d+)\)(\d)')   # (N)N — 2Ki 11:6
PATTERN_DD = re.compile(r'\(\((\d+)\)\)')    # ((N)) — 1Ki 22:52, 1Ch 12:40
PATTERN_N  = re.compile(r'\b(\d+)\)')        # N) — Psalms, 3Jn, Rev

def detect_markers(text: str) -> list[dict]:
    """Detect verse markers, returning list of {type, verse, pos, match}."""
    markers = []
    for pattern, ptype in [(PATTERN_PN, "(N)N"), (PATTERN_DD, "((N))"), (PATTERN_N, "N)")]:
        for m in pattern.finditer(text):
            markers.append({
                "type": ptype,
                "verse": int(m.group(1)),
                "pos": m.start(),
                "match": m.group(0),
            })
    return sorted(markers, key=lambda x: x["pos"])
```
