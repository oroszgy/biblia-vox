# Phase 2.5: Data Quality & Correction

## Goal

Fix Bible text data quality issues: convert to JSONL format, split embedded verses, and correct versification schema errors — so that `bibliavox text validate --all` passes for all 66 SZIT books.

## Scope

Three plans:

1. **02.5-01**: JSONL Conversion — SZIT JSON → JSONL with USX codes, NFC normalization
2. **02.5-02**: Verse Splitting — detect embedded verse markers (`N)`, `((N))`, `(N)N`) and split
3. **02.5-03**: Schema Fixes — correct versification.json for DAN, MAL, and off-by-one issues

## Decisions

### Data Format

- **JSONL over JSON**: Each line is `{"book": "GEN", "chapter": 1, "verse": 1, "text": "..."}` — streamable, diffable, processable line-by-line
- **Coexist**: Raw `H_Kaldi_SZIT.json` stays in `data/raw/text/`. JSONL is a processed artifact in `data/processed/text/`
- **USX codes**: Book field uses USX codes (e.g., "GEN"), not English names ("Genesis")
- **NFC normalization**: Applied during JSONL conversion (first pass)

### Verse-Splitting Strategy

- **Pattern detection**: Regex `\d+\)` found in 67 verses across Psalms, 1Ki, 2Ki, 1Ch, 3Jn, Rev
- **Three pattern types**:
  - `N)` — most common, especially Psalms superscriptions (e.g., PSA 3:1 contains `2)`)
  - `((N))` — 1Ki 22:52, 1Ch 12:40
  - `(N)N` — 2Ki 11:6 (format: `(6)7`)
- **Psalms edge case**: Some Psalms have both `2)` and `3)` in verse 1 — superscription spans verses 1-2, content starts at verse 3
- **Splitting logic**: JSONL → JSONL transformation; detects pattern, splits text, assigns correct verse numbers
- **Taskfile target**: `text:fix-verses` for reproducibility

### Schema Fixes

- **DAN 3**: Expected 91 verses, got 30 — deuterocanonical additions (Prayer of Azariah, Susanna, Bel) not in SZIT. Schema should match SZIT reality (30 verses), not Catholic canon with additions.
- **MAL 4**: Our schema has 3 chapters, SZIT has 4. Schema needs 4th chapter.
- **Off-by-one books** (1SA, JON, NAM, HAB, 2CO, 3JN): Investigate whether verse-splitting fixes these or if schema needs adjustment.

### Pipeline Architecture

```
H_Kaldi_SZIT.json (raw, Python literal format)
    │
    ▼ [text:convert-jsonl]
szit.jsonl (USX codes, NFC, one verse per line)
    │
    ▼ [text:fix-verses]
szit-fixed.jsonl (split verses, corrected numbering)
    │
    ▼ [text:validate --all]
validation report (should pass 66/66)
```

## Gray Areas Resolved

- **JSONL schema**: book (USX), chapter (int), verse (int), text (str) — flat, no nesting
- **Verse splitting as preprocessing**: Separate task from JSONL conversion — composable pipeline
- **Raw data preserved**: No mutation of source files
- **Schema vs source conflicts**: Schema should match SZIT source, not idealized canon
