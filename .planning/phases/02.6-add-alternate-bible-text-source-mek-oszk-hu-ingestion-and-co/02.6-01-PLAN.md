    - Test: parse_and_cache_mek_chapters splits full book HTML into chapter-level files, decoding Latin-2 (ISO-8859-2) to UTF-8, and caches them at data/raw/text/mek/{BOOK}_{CHAPTER}.html.
    - Test: parse_mek_chapter uses BeautifulSoup to extract verses from chapter-level HTML:
      - Chapter tags look like: &lt;small&gt;&lt;font color="AAAAAA"&gt;Ter 1&lt;BR&gt;&lt;/font&gt;&lt;/small&gt; or &lt;small&gt;&lt;font color="AAAAAA"&gt;&lt;p align=justify&gt;Ter 1&lt;BR&gt;&lt;/font&gt;&lt;/small&gt;
      - Verse tags look like: &lt;small&gt;&lt;font color="AAAAAA"&gt;Ter 1.1&lt;BR&gt;&lt;/font&gt;&lt;/small&gt;
      - Verily extracts the text node(s) immediately following the verse tag up to the next tag.
      - Suffixes (like 1.1a, 1.1b) are combined into a single verse entry (separated by a space) if they share the same integer verse number.
      - Text is properly stripped, whitespace-collapsed, and NFC-normalized.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Network -> local disk | Scraping remote MEK HTTP server; potential malicious HTML or SSRF injection |
| User flags -> file writer | User chose custom output path; possibility of writing files outside bounds |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.6-01 | Tampering | `mek_source.py` downloader | mitigate | Strictly check HTTP status codes. BeautifulSoup parser does not evaluate inline scripts or CSS. |
| T-02.6-02 | Information Disclosure | `mek_source.py` file writer | mitigate | Sanitize book USX codes and chapter numbers before joining paths. Limit write operations strictly to the configured data directory (no path traversal). |
| T-02.6-03 | Denial of Service | `mek_source.py` HTTP client | mitigate | Use strict timeouts (e.g. 10.0s) in HTTP requests and restrict parallel worker count to avoid triggering remote block/ban. |
</threat_model>
