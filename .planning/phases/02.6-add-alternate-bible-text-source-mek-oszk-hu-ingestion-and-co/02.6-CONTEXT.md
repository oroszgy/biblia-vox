# Phase 2.6: Alternate Text Source & Cross-Source Coverage Validation - Context

**Gathered:** 2026-05-30
**Status:** Ready for planning

<domain>
## Phase Boundary

Ingest the full Hungarian Catholic Bible text from mek.oszk.hu HTML pages as a second corpus (all 73 books), then cross-compare it against the existing `szit-fixed.jsonl` to surface coverage gaps and textual discrepancies. Delivers a `mek.jsonl` processed corpus and a `text cross-validate` CLI command that produces both a Rich summary table and a JSONL diff file on disk.

</domain>

<decisions>
## Implementation Decisions

### MEK HTML Parsing
- **D-01:** Use **BeautifulSoup** to parse mek.oszk.hu chapter HTML pages — explicit DOM navigation, robust to whitespace/attribute variation, easy to maintain.
- **D-02:** Cache raw HTML chapter files in `data/raw/text/mek/` before parsing — reproducible without re-fetching. One file per chapter (e.g., `GEN_1.html`).

### Coverage Scope
- **D-03:** Scrape and compare **all 73 Catholic books** (full pass). If MEK does not have a book, report it as missing rather than treating absence as an error.

### Cross-Source Comparison Output
- **D-04:** New CLI command: `bibliavox text cross-validate` — prints a Rich table summary to stdout and writes a JSONL diff file to disk.
- **D-05:** JSONL diff format: one entry per discrepancy — `{"book", "chapter", "verse", "source", "severity", "type", "szit_text", "mek_text"}`. Severity levels: `missing_verse`, `missing_chapter`, `missing_book`, `text_diff`.
- **D-06:** Taskfile target: `text:cross-validate`.

### MEK Text Storage
- **D-07:** Raw HTML cached at `data/raw/text/mek/{BOOK}_{CHAPTER}.html` (chapter-per-file).
- **D-08:** Processed corpus at `data/processed/text/mek.jsonl` — same JSONL schema as `szit-fixed.jsonl`: `{"book": "USX_CODE", "chapter": int, "verse": int, "text": str}`.

</decisions>
