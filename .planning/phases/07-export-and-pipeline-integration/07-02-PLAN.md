Add the following targets to `Taskfile.yml` after the existing `align:*` targets:

```yaml
  export:fetch-text:
    desc: Ensure canonical text corpus is available (mek.jsonl)
    cmds:
      - task: text:ingest-mek
    status:
      - test -f data/processed/text/mek.jsonl

  export:prepare-audio:
    desc: Prepare audio for gold chapters (download + convert + index)
    cmds:
      - task: audio:prepare-all

  export:align:
    desc: Run alignment on gold chapters in Docker with GPU
    cmds:
      - docker compose run --rm align python -m bibliavox.main align evaluate-gold {{if .MODEL}}--model "{{.MODEL}}"{{end}}
    status:
      # Skip if evaluation data exists and not forced
      - '{{if .FORCE}}false{{else}}test -f data/evaluation/summary.json{{end}}'

  export:jsonl:
    desc: Export alignment results to JSONL (GOLD=true for gold chapters, MODEL=... to override)
    vars:
      MODEL: '{{default "microsoft/VibeVoice-ASR-HF" .MODEL}}'
    cmds:
      - uv run bibliavox export jsonl --gold --model "{{.MODEL}}"{{if .FORCE}} --force{{end}}
    deps:
      - export:fetch-text

  export:run:
    desc: Run full pipeline on gold chapters (text → audio → align → export)
    vars:
      MODEL: '{{default "microsoft/VibeVoice-ASR-HF" .MODEL}}'
    cmds:
      - task: export:jsonl
        vars:
          GOLD: "true"
          MODEL: "{{.MODEL}}"
          FORCE: "{{.FORCE}}"
    deps:
      - export:prepare-audio
      - export:align
```

Key design decisions:
- D-08: `export:run` chains `export:prepare-audio` → `export:align` → `export:jsonl` via deps
- D-09: Fail-fast — if any dep fails, go-task stops (built-in behavior)
- D-10: Default MODEL is `microsoft/VibeVoice-ASR-HF` via `{{default ...}}`
- D-14: FORCE variable passed through to disable idempotency checks
- Variable syntax uses go-task `{{.VAR}}` pattern (not CLI flags) per existing convention
- `export:align` uses `status` to skip if evaluation data exists (unless FORCE=true)
- `export:fetch-text` uses `status` to skip if mek.jsonl already exists
