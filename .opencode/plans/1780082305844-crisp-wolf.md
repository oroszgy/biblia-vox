# Verify-Work Execution Plan

## Goal
Run the verify-work workflow end-to-end for conversational UAT with persistent state, producing `{phase_num}-UAT.md`, and auto-routing to diagnosis + fix planning when issues are found.

## Recommended Approach
1. **Initialize routing context**
   - Read workflow + template as source of truth:
     - `~/.config/opencode/get-shit-done/workflows/verify-work.md`
     - `~/.config/opencode/get-shit-done/templates/UAT.md`
   - Discover active sessions first via `.planning/phases/**/-UAT.md`.
   - Branch strictly per workflow gates:
     - Active session(s) + no phase arg -> present resume options.
     - No active session + no phase arg -> ask for phase number.
     - Phase arg provided -> init phase context and create/resume target UAT file.

2. **Resolve phase and load phase context**
   - Run `init.verify-work` for selected phase and parse required fields:
     `planner_model`, `checker_model`, `commit_docs`, `phase_found`, `phase_dir`, `phase_number`, `phase_name`, `has_verification`, `uat_path`.
   - Validate phase directory exists and identify summary inputs:
     - `"${phase_dir}"/*-SUMMARY.md`

3. **Build UAT test set from user-observable outcomes**
   - Extract tests from SUMMARY accomplishments and user-facing behavior only.
   - Skip internal-only items (refactors/types-only changes).
   - Apply cold-start smoke test injection when startup/db/docker path heuristics are matched.
   - If enabled/available, run automated UI verification gate and queue only subjective checkpoints.

4. **Create or resume persistent UAT session**
   - Target output path: `.planning/phases/XX-name/{phase_num}-UAT.md`.
   - Ensure template-compliant sections:
     - frontmatter (`status`, `phase`, `source`, `started`, `updated`)
     - `## Current Test`
     - `## Tests`
     - `## Summary`
     - `## Gaps`
   - For resume flows: locate first `result: [pending]`, refresh `Current Test`, continue.

5. **Run conversational UAT loop (one test at a time)**
   - Render checkpoint using `gsd-sdk query uat.render-checkpoint --file "$uat_path" --raw`.
   - Output checkpoint exactly as rendered (no extra text).
   - Process plain-text user responses with automatic classification:
     - pass keywords -> `pass`
     - skip keywords -> `skipped` (+reason)
     - blocked context -> `blocked` (+`blocked_by` inference)
     - all other responses -> `issue` (+severity inference; default `major`)
   - Update summary counts and timestamps with batched write policy:
     - write immediately on issue
     - write every 5 passes
     - write on completion

6. **Complete session and commit artifact**
   - Compute final status:
     - `partial` if pending/blocked/skipped-without-reason remains
     - `complete` otherwise
   - Set `Current Test` to `[testing complete]`.
   - Commit UAT artifact with workflow-prescribed commit pattern.

7. **Issue routing (mandatory when issues > 0)**
   - Auto-run diagnosis workflow:
     - `~/.config/opencode/get-shit-done/workflows/diagnose-issues.md`
   - Populate gap root-cause fields in UAT (`root_cause`, `artifacts`, `missing`, `debug_session`).
   - Auto-run gap closure planning with `gsd-planner` (`gap_closure` mode).
   - Auto-run plan verification with `gsd-plan-checker`.
   - If checker fails, run revision loop (max 3 iterations).
   - Final handoff message: `/new` then `/gsd-execute-phase {phase} --gaps-only`.

8. **No-issue routing and phase progression gates**
   - Run artifact scan gate (`audit-open`) for current phase; require explicit acknowledgement to proceed if open artifacts exist.
   - Enforce security gate:
     - if security enforcement enabled and no SECURITY report -> require `/gsd-secure-phase {phase}`
     - if threats remain open -> block advancement
   - If gates pass, execute transition workflow:
     - `~/.config/opencode/get-shit-done/workflows/transition.md`

## Practical Defaults
- If user does not provide a phase and no active UAT exists, request phase number (single targeted prompt).
- If user asks for recommendation, default to current project focus from `.planning/STATE.md` (currently Phase 3).
- If severity is unclear, infer `major`.
- If blocked reason is unclear, infer `blocked_by: other`.

## Critical Files/Artifacts
- Workflow: `~/.config/opencode/get-shit-done/workflows/verify-work.md`
- Template: `~/.config/opencode/get-shit-done/templates/UAT.md`
- UAT artifact: `.planning/phases/XX-name/{phase_num}-UAT.md`
- Inputs: `.planning/phases/XX-name/*-SUMMARY.md`
- State context: `.planning/STATE.md`, `.planning/ROADMAP.md`
- Diagnosis workflow: `~/.config/opencode/get-shit-done/workflows/diagnose-issues.md`
- Transition workflow: `~/.config/opencode/get-shit-done/workflows/transition.md`

## Verification Checklist (Execution Readiness)
- Session discovery is run first and routing follows active/no-active rules.
- Selected phase resolves through `init.verify-work` with valid `phase_dir` and `uat_path`.
- UAT file structure exactly matches template sections and status lifecycle.
- Tests are user-observable and presented one at a time via rendered checkpoint.
- Response classification updates test result + summary + gap entries correctly.
- Batched persistence policy is respected (issue / every 5 passes / completion).
- Completion routing is correct for both branches:
  - issues present -> diagnose + planner + checker (+revision loop)
  - no issues -> artifact scan + security gate + transition
- Final output is ready for `/gsd-execute-phase {phase} --gaps-only` when gaps exist.
